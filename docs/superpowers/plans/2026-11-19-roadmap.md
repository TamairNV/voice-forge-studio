# Voice Forge Studio: roadmap (game-dev fork of VoiceStudio)

Fork of debpalash/VoiceStudio at upstream `8f6c11343` (2026-11-18), branch `game-dev`.
It keeps VoiceStudio's Python backend (engines, process isolation, model catalogue, licence
records, watermark, OpenAI-compatible API, MCP). It drops the Electron, mobile and store
apps, dubbing, dictation, long-form, cloud, Pro and telemetry. Voice Forge's game features
and web UI (TamairNV/voice_forge) go on top.

Licence: the code stays AGPL-3.0, with upstream notices kept and a modification notice added.
Generated audio is not AGPL. Each model's own licence decides whether its audio can ship.

## Decisions (Tamair, 2026-11-19)

- Game engine: **Unity**.
- Fork VoiceStudio. Don't port it into voice_forge.
- Machines:
  - **Mac M4 Pro, 24 GB** (main studio, MLX/Metal).
  - **Windows PC with RTX 3070 8 GB**, possibly dual-booting Linux, as a CUDA render worker.

## Phases (each gets its own plan file when it starts)

1. **Fork and strip.** API-only backend, slim engine and model set, VoxCPM2 default, green
   tests. Plan: `2026-11-19-phase1-fork-and-strip.md`.
2. **Port Voice Forge.** Characters, emotion profiles, casts, scenes and takes on the
   backend's database. Voice Forge's `static/` pages become the UI, with its endpoint paths
   kept so its MCP server and agents keep working. Port the Maya-1 engine. Import voice_forge `data/`.
3. **Engines and licence filter.** Per-character engine choice. A `shipping` project flag
   refuses any engine whose licence record is non-commercial or unreviewed (the Phase 1
   catalogue test already checks every model has a record).
4. **Unity pipeline.**
   - Dialogue sheet import (CSV/JSON: `line_id, character, text, emotion, context`), stable
     file names (`<character>_<line_id>.wav`), re-render only lines whose text, voice or
     settings changed.
   - Export to 48 kHz mono 16-bit WAV, loudness to −23 LUFS integrated / −1 dBTP (new: upstream
     only does peak normalisation). Bark variations (N takes, best by speaker similarity), and
     a batch Whisper script check.
   - `manifest.json` per export: line id, file, duration, transcript, word timings.
   - Lip-sync JSON from Whisper word timestamps, plus phoneme timings for uLipSync.
5. **3070 render worker.** Run the same backend on the PC (Linux), bound to its Tailscale
   address only and behind upstream's API-key gate (`BearerKeyMiddleware`). The Mac gets a
   `remote` engine that sends IndexTTS, GPT-SoVITS and full-precision VoxCPM2 jobs to it.
6. **Unity package.** Editor window that pulls an export (`manifest.json`), imports
   AudioClips and creates `DialogueLine` ScriptableObjects with lip-sync data. Optional
   in-editor "render this line" over the local API.
7. **Later.** MOSS-SoundEffect via MLX port, and fully removing the OmniVoice code (Phase 1
   only makes it non-default and hidden).
